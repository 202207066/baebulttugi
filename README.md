# 배불뚜기 — 알러지 대응 스마트 급식 식단 관리 시스템

피급식자의 알러지 정보를 등록하고, 그 정보를 반영해 식단을 자동으로 조합하며,
원가와 소요량까지 함께 관리하는 Windows 데스크톱 프로그램입니다.
데이터는 구글 스프레드시트에 저장되어 팀원 간에 공유됩니다.

> **처음 받으셨다면 [SECURITY.md](SECURITY.md)를 먼저 읽어 주세요.**
> 저장소 히스토리에 남은 구글 서비스 계정 키를 폐기하는 절차가 적혀 있습니다.

## 화면 구성

| 화면 | 하는 일 |
|---|---|
| 대시보드 | 오늘 식단, 총 피급식자 수, 알러지 성분별 대상자 현황 |
| 식단 자동 조합 | 목표 영양소를 입력하면 알러지를 제외한 식단 3안을 추천 |
| 메뉴(레시피) 관리 | 메뉴별 열량·재료·알러지 정보 등록 |
| 식재료 원천 DB | 구글 시트의 임의 탭을 표로 열어 편집, CSV 가져오기/내보내기 |
| 피급식자 알러지 관리 | 대상자 등록·수정·삭제, 그날 메뉴와의 교차 위험 스캔 |
| 원가 / 소요량 계산 | 인원수·목표 급식비 기준 원가 산출, CSV 내보내기 |
| 이벤트 및 절기 달력 | 공휴일·절기(공공데이터 API) + 직접 등록한 일정 |

## 개발 환경

- Windows 10 이상
- .NET 8 SDK
- Visual Studio 2022 (또는 `dotnet build`)

WPF 프로젝트라 **Windows에서만 빌드·실행됩니다.**

## 처음 실행하기

### 1. 저장소 클론

```bash
git clone https://github.com/202207066/baebulttugi.git
cd baebulttugi
```

### 2. 구글 클라우드 설정

1. [Google Cloud Console](https://console.cloud.google.com)에서 프로젝트를 만듭니다.
2. **API 및 서비스 → 라이브러리**에서 다음 두 가지를 사용 설정합니다.
   - Google Sheets API
   - Google Drive API
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **데스크톱 앱**
4. 내려받은 JSON 파일의 이름을 `credentials.json`으로 바꿔
   `wpf/` 폴더에 둡니다.

> 이 프로그램은 **OAuth 사용자 인증**만 사용합니다.
> 서비스 계정 키(`type: service_account`)를 `credentials.json`으로 두면
> 로그인 단계에서 실패합니다.

### 3. 설정 파일 만들기

```bash
cd wpf
cp appsettings.sample.json appsettings.json
```

`appsettings.json`을 열어 값을 채웁니다.

| 항목 | 설명 |
|---|---|
| `SpreadsheetId` | 구글 스프레드시트 URL의 `/d/` 와 `/edit` 사이 문자열 |
| `TemplateSpreadsheetId` | 사용자별 개인 DB를 만들 때 복사할 원본. 비우면 `SpreadsheetId`를 사용 |
| `HolidayApiKey` | [공공데이터포털](https://www.data.go.kr) 특일 정보 서비스키 (없으면 공휴일 표시만 생략) |
| `Sheets.*` | 각 기능이 사용할 탭 이름 |

`appsettings.json`과 `credentials.json`은 `.gitignore`에 등록되어 있어
커밋되지 않습니다.

### 4. 빌드 및 실행

```bash
dotnet build wpf/wpf.csproj
dotnet run --project wpf/wpf.csproj
```

또는 Visual Studio에서 `wpf/wpf.sln`을 열고 F5.

첫 실행 시 브라우저가 열리며 구글 로그인을 요구합니다.
승인하면 `wpf/token.json/` 폴더에 토큰이 저장되어 다음부터는 자동 로그인됩니다.

## 스프레드시트 구조

프로그램은 아래 탭들을 사용합니다. 탭 이름은 `appsettings.json`에서 바꿀 수 있습니다.
**1행은 헤더**로 취급합니다.

### `MenuDatabase` — 메뉴(레시피)

| 열 | 항목 | 필수 | 예 |
|---|---|---|---|
| A | 메뉴명 | ✅ | 소불고기 |
| B | 칼로리 | | 180 kcal |
| C | 재료 | | 소고기, 양파, 간장 |
| D | 유발 알러지 | | 대두, 밀 |
| E | 분류 | 권장 | 주찬 |
| F | 탄수화물(g) | | 12 |
| G | 단백질(g) | | 18 |
| H | 지방(g) | | 9 |

- **E열(분류)** 에는 `밥` / `국` / `주찬` / `부찬` 중 하나를 넣습니다.
  비워 두면 메뉴 이름으로 추정하는데, "국수"가 국으로 잡히는 식의
  오분류가 생길 수 있으니 채우는 편이 좋습니다.
- **F~H열**이 비어 있으면 자동 조합 결과의 탄·단·지가 0으로 표시됩니다.

### `알러지 인원` — 피급식자

| 열 | 항목 | 예 |
|---|---|---|
| A | ID | 1 |
| B | 성명 | 홍길동 |
| C | 구분 | 일반 |
| D | 특이 알러지 성분 | 땅콩, 대두 |
| E | 비고 | |

여기에 등록된 알러지 성분이 식단 자동 조합에서 **제외 기준**이 됩니다.

### `식단` — 저장된 추천 식단

| A 구분 | B 밥 | C 국 | D 주찬 | E 부찬 | F 칼로리 |
|---|---|---|---|---|---|

### `Event` — 일정

| A 날짜(yyyy-MM-dd) | B 내용 |
|---|---|

### `원가` — 식재료 단가 (선택)

| A 식단명 | B 식재료명 | C 분류 | D 1인당 소요량 | E 단위 | F 단가 |
|---|---|---|---|---|---|

이 탭이 없으면 원가 계산 화면은 예시 데이터로 동작하며,
목록에 **"(데모 데이터)"** 라고 표시됩니다.

### `Dashboard` — 대시보드 요약 (선택)

2행 A~E: 총 인원, 알러지 인원, 식단 상태, 오늘 메뉴, 대치 메뉴

> 총 인원과 알러지 인원은 `알러지 인원` 탭에서 직접 세므로,
> 이 탭이 없어도 대시보드는 동작합니다.

## 식단 자동 조합이 동작하는 방식

1. `알러지 인원` 탭의 모든 알러지 성분을 모읍니다.
2. `MenuDatabase`에서 그 성분이 재료·알러지 열에 포함된 메뉴를 후보에서 제외합니다.
3. 남은 후보를 밥 / 국 / 주찬 / 부찬으로 나눕니다.
4. 무작위로 200가지 조합을 만들어 보고, 그중
   - 한 끼에 같은 메뉴가 겹치지 않고
   - 자극적인(맵거나 짠) 메뉴가 2개를 넘지 않으며
   - 앞서 추천한 조합과 다른 것 중에서
   - 목표 영양소와의 상대 편차가 가장 작은 조합을 고릅니다.
5. 이 과정을 3번 반복해 서로 다른 3안을 만듭니다.

## 프로젝트 구조

```
wpf/
  App.xaml.cs              시작 흐름 (설정 확인 → 로그인 → 개인 DB → 나이대 → 메인)
  AppConfig.cs             appsettings.json 읽기
  GoogleSheetsService.cs   구글 시트/드라이브 공용 서비스 + 공통 헬퍼
  Main.xaml(.cs)           사이드바 + 대시보드
  Menu_table.xaml(.cs)     식단 자동 조합
  MenuInputPage.xaml(.cs)  메뉴 관리
  ingredients.xaml(.cs)    식재료 원천 DB
  AllergyManagementPage.*  피급식자 알러지 관리
  CalculatePage.xaml(.cs)  원가 계산
  EventCalendar.xaml(.cs)  달력
  PromptDialog.cs          간단한 입력 대화상자
legacy/test1/              초기 WinForms 프로토타입 (빌드 대상 아님)
```

인증은 `App.xaml.cs`에서 **한 번만** 수행하고, 만들어진 `GoogleSheetsService`
인스턴스를 `AppServices`에 담아 모든 화면이 공유합니다.
각 화면에서 따로 인증하지 않습니다.

## 자주 겪는 문제

**"설정 필요" 창이 뜨고 종료됩니다**
`wpf/appsettings.json`이 없거나 `SpreadsheetId`가 비어 있습니다. 위 3단계를 확인하세요.

**"인증 파일 필요" 창이 뜹니다**
`wpf/credentials.json`이 없습니다. 위 2단계를 확인하세요.

**로그인은 되는데 시트를 못 읽습니다**
해당 스프레드시트에 로그인한 구글 계정의 접근 권한이 있는지 확인하세요.

**공휴일이 표시되지 않습니다**
`HolidayApiKey`가 비어 있거나 잘못되었습니다. 키가 없어도 나머지 기능은 정상 동작합니다.

**추천 식단의 탄·단·지가 전부 0입니다**
`MenuDatabase`의 F~H열이 비어 있습니다.

**"조합할 메뉴가 부족합니다"**
해당 자리(밥/국/주찬/부찬)에 넣을 메뉴가 없습니다. E열 분류를 채우거나,
등록된 알러지 때문에 후보가 모두 걸러진 것은 아닌지 확인하세요.

## 남은 과제

- 여러 사람이 동시에 편집할 때의 충돌 처리 (현재는 나중에 저장한 쪽이 이깁니다)
- 저장된 추천 식단에 날짜 열 추가 → 날짜별 식단 조회
- 대시보드 UI를 코드 조립에서 XAML + 데이터 바인딩으로 이전
- 단위 테스트 (특히 조합 알고리즘과 알러지 필터)
