# 주간 식단 자동 조합

## 동작

- 원본 `TemplateSpreadsheetId`의 트랙A(만 3~5세) 또는 트랙B(만 6~18세)를 매 실행마다 읽는다. TemplateSpreadsheetId가 비어 있으면 SpreadsheetId를 사용한다.
- 선택한 날짜가 속한 월~일을 대상으로 한다. 기본은 월~금 점심 5끼이고 요일 및 조식·중식·석식을 선택할 수 있다.
- 한 끼마다 밥류·국류·주찬·부찬·김치류·후식류를 각 1개 선택한다. 기존 트랙의 간식류는 후식류 후보로 매핑한다.
- 입력한 탄수화물·단백질·지방 목표는 선택한 모든 끼니에 동일하게 적용한다. 대상 연령의 실제 메뉴 1인분 영양량을 합산하며 배식량을 임의로 늘리거나 줄이지 않는다.
- 여러 초기 조합에서 각 분류의 메뉴를 교체하며 목표 편차를 줄이는 근사 탐색이다. 전역 최적해나 목표 충족을 보장하지 않는다. 초기 허용 편차 15%는 앱의 조합 비교 설정이며 영양 권장 기준이 아니다.
- 결과 전체를 개인 DB의 `메뉴` 탭에 추가한다. 같은 주를 새로 생성하면 이전 결과를 보존하고 새로운 기록을 추가한다. 저장 실패 시 화면의 재시도 버튼은 동일 식단 ID로 중복을 확인한다.
- 기존 9열 식단 표의 내용은 유지하고 헤더 명칭을 정리한 뒤 영양·출처·상태 열을 추가한다. 알려지지 않은 표 구조이면 덮어쓰지 않고 오류를 표시한다.
- 기존 레시피 직접 입력 화면은 `레시피` 탭을 사용한다. 주간 결과와 단품 레시피를 같은 탭에 섞지 않는다. 직접 입력 레시피가 자동으로 원본 트랙에 등록되지는 않는다.

## 영양정보 입력 기준

트랙 3행의 헤더는 K=추가 알레르기 코드, L=탄수화물(g), M=단백질(g), N=지방(g), O=열량(kcal), P=1인분 중량(g), Q=영양정보 출처이다. 기존 A:J 및 K열의 추가 알레르기 값은 보존한다.

1. 해당 연령에 제공하는 실제 레시피와 1인분 배식량을 기준으로 한다. 같은 음식도 연령별 분량이 다르면 트랙별 수치를 따로 입력한다.
2. 원본 레시피의 1인분 영양정보가 있으면 그 값을 사용한다. 직접 계산한다면 재료별 `사용량(g) × 해당 식품의 100g당 영양량 ÷ 100`을 합산하고, 여러 인분의 레시피라면 제공 인원수로 나눈다. 원재료/조리된 음식 등 데이터의 기준 상태를 맞춰야 한다.
3. 동일한 조리 음식의 100g 기준 공공 데이터가 있다면 `100g당 영양량 × 실제 제공량(g) ÷ 100`으로 환산한다. 음식 이름이 비슷하다는 이유만으로 다른 조리법의 값을 확정값으로 사용하지 않는다.
4. Q열에 레시피 문서명 또는 식품코드·자료명·기준량을 남긴다. 공공 데이터 확인: [식약처 K-FIND](https://various.foodsafetykorea.go.kr/nutrient/).
5. L:N은 필수이며 실제 0은 숫자 0으로 입력한다. 미확인 정보는 공란으로 둔다. 공란·음수·비정상 숫자가 있는 메뉴는 자동 조합에서 제외한다. O가 없으면 탄수화물×4 + 단백질×4 + 지방×9로 열량을 추정한다.

제공된 1월 식단표 PDF는 식사/간식 묶음의 열량·단백질을 보여 주며 모든 개별 메뉴의 탄수화물·지방·배식량은 제공하지 않는다. 이 총량을 메뉴별로 균등 배분하지 않는다. 현재 원본 트랙의 영양정보가 비어 있어 실제 영양 목표 식단 생성은 아직 불가능하다. 최소한 6개 분류 각각에 영양정보가 있는 후보가 필요하며, 다양한 주간 조합에는 여러 후보가 필요하다.

## 데이터 호환성과 한계

- 트랙 제목·요약·분류 구분 행을 제외하고 메뉴ID·메뉴명 헤더를 찾아 읽는다.
- 트랙B의 메뉴ID가 구간마다 중복되므로 ID·정규화 분류·메뉴명을 결합해 내부 키와 출처 기록에 사용한다. 원본 ID는 변경하지 않는다.
- 알레르기 제외는 개인 DB 명단과 원본의 숫자/원문자 코드를 비교한다. 누락된 코드의 안전성은 판정할 수 없다. 명단 읽기가 실패하면 필터를 해제한 채 진행하지 않고 오류를 표시한다.
- 한 끼 6개 메뉴 이름은 중복하지 않는다. 여러 끼니 사이의 반복은 줄이도록 점수를 적용하지만 금지하지 않는다. 고정 메뉴는 모든 끼니에 반복 적용된다.
- 6~18세는 하나의 메뉴 풀을 사용한다. 세부 연령에 따른 권장 섭취량·개별 건강 상태를 자동 판정하지 않으며 목표 입력값은 사용자가 정한다.
- 원본 트랙은 읽기만 하고 주간 결과는 개인 DB에만 저장한다. 개인 DB 초기화가 실패하면 원본 쓰기를 방지하기 위해 앱 시작을 중단한다.

## 검증

`dotnet build wpf.csproj`

`dotnet run --project Tests/PlannerChecks.csproj`

검증 프로그램은 가상 Google HTTP 응답만 사용한다. 주간 5/21끼, 6종 합산, 연령 매핑, 빈 영양값·잘못된 목표, 알레르기 코드, 목표 미달 표시, 일괄 저장 요청, 재시도 중복 방지, 기존 표 구조 보호, WPF 화면 생성을 검사한다. 선택적으로 첫 인자에 트랙 행 JSON, 두 번째 인자에 UI PNG 출력 경로를 전달할 수 있다.
