# 교수님 피드백 반영 안내

2026-09-20 기준. 지정한 WPF 프로젝트를 수정하고, 실행 가능한 Release 배포 폴더를 만들었습니다.

## 반영한 내용

| 피드백 | 반영 내용 |
|---|---|
| 구글 인증 중 창 유지 | 로그인 창을 열어 둔 상태에서 브라우저 인증과 개인 시트 준비를 진행합니다. 진행 문구·로딩 막대를 표시합니다. |
| 최초 실행 안내 | 비어 있는 메뉴·대상자·원가 자료와 연결 오류를 구분합니다. 빈 식단은 ‘아직 식단이 작성되지 않았습니다.’로 표시합니다. |
| 대시보드·캘린더 연결 | 식단이 없는 화면에서 ‘식단 만들기’로 이동할 수 있습니다. 캘린더에서 선택한 날짜의 주를 넘깁니다. |
| 대체 식단 배포 | 대체 식단이 준비되었다는 가짜 표시·확정 메시지를 제거했습니다. 새 개인 시트의 대상자·인원 예시는 비웁니다. 기존 개인 자료와 원본의 기본 예시 식단은 보존합니다. |
| 진행 상황 | 메뉴 불러오기·식단 생성/저장·알레르기 자료 조회·시트 전환·CSV 업로드 등에 작업 설명과 로딩 막대를 표시합니다. 정확한 진행률을 알 수 없는 작업은 움직이는 막대로 표시합니다. |
| 용어·사용 흐름 | ‘식단 만들기’, ‘꼭 포함할 메뉴 선택’, ‘프로그램이 골라주기’로 기능을 설명합니다. 예전 3안 추천 설명도 실제 주간 생성 흐름에 맞췄습니다. |
| 기존 DB 호환 | 메뉴의 기존 열 이름을 읽고, 같은 날짜·끼니·연령에는 최신 저장 식단을 표시합니다. 알레르기 명단은 열 제목으로 읽으며 기존 연령·성별·대체식품을 보존합니다. |
| 원가·소요량 | 임의의 데모 원가를 제거했습니다. g↔kg, ml↔L, 단가 기준량을 반영하며 1인당 원가를 정수로 반올림한 뒤 인원수와 곱하던 오류를 수정했습니다. |
| 시트 설명 | 원본에 ‘사용안내’ 탭을 추가했습니다. 각 탭의 목적·영양정보 기준·원가 입력법을 설명합니다. ‘원가’ 탭도 열 제목을 갖춰 추가했습니다. |
| JSON 준비 없애기 | 배포용 시트 연결·데스크톱 OAuth 설정을 앱에 포함했습니다. 사용자가 appsettings.json이나 credentials.json을 별도로 만들 필요가 없습니다. |
| 원본 시트 접근 | 앱 왼쪽에 ‘공공 메뉴 자료 보기’와 ‘내 식단 자료 보기’를 추가했습니다. 실제 접근 권한은 Google 공유 설정을 따릅니다. |

## 실행 방법

`배불뚝이_피드백반영` 폴더의 `wpf.exe`를 실행합니다. 다른 PC로 옮길 때는 EXE 하나가 아니라 폴더 전체를 옮겨 주세요. Windows용 .NET 8 Desktop Runtime이 필요한 배포본입니다.

1. 구글 계정으로 로그인합니다.
2. 처음이면 원본을 복사해 개인 드라이브에 내 식단 자료를 준비합니다. 이후에는 앱 표식이 있는 본인 소유 시트를 찾아 재사용합니다.
3. 기존 버전의 `user_sheet_id.txt`가 실행 폴더에 있으면, 본인 소유·편집 가능한 시트인지 확인해 연결을 이어 갑니다. 새 배포 폴더로 옮겼고 구버전 시트에 앱 표식도 없으면 기존 ID 파일도 함께 옮겨야 자동 인계할 수 있습니다.
4. ‘식단 만들기’에서 연령·주·요일·끼니·한 끼 목표 영양소를 입력합니다.

## 원가 입력

원가 탭은 A부터 순서대로 `식단명 / 식재료명 / 분류 / 1인당 소요량 / 단위 / 단가(원) / 단가 기준량 / 단가 단위`입니다. 같은 식단명의 식재료 행을 합산합니다.

예: 1인분 120g, 1kg에 28,000원이면 D=120, E=g, F=28000, G=1, H=kg로 입력합니다. 1인당 3,360원, 300명은 1,008,000원입니다. G/H가 비어 있으면 기존 방식대로 E 단위 1개당 F원으로 계산합니다. 포장 구매량 올림, 폐기율, 식단 메뉴와 원가표의 자동 매칭은 포함하지 않습니다.

## 아직 구분해야 하는 부분

- **실제 영양 데이터가 필요합니다.** 현재 트랙A·B에 메뉴별 탄수화물·단백질·지방이 비어 있습니다. 각 분류에 실제 1인분 영양정보를 갖춘 후보가 있어야 자동 조합할 수 있습니다. 이번 수정에서 가짜 영양 수치를 채우지 않았습니다.
- **실제 계정의 로그인부터 저장까지 통합 검증은 남아 있습니다.** 코드 빌드, 가상 Google 응답을 사용한 검증, 화면 렌더링을 완료했습니다. 새 계정 OAuth 동의·Drive 복사·실제 Sheets 저장은 이 배포본으로 확인해야 합니다.
- **JSON을 전부 없앤 것은 아닙니다.** 사용자가 직접 준비하는 두 설정 파일을 없앴습니다. .NET 실행용 `wpf.deps.json`·`wpf.runtimeconfig.json`과 자동 생성되는 로그인/화면 설정 자료는 남습니다. 로그인 자료와 화면 설정은 사용자 AppData에 저장합니다.
- 데스크톱 OAuth 설정을 앱에 포함하는 것은 사용자 준비 과정을 줄이는 방법입니다. 앱 안의 값은 추출 가능하므로 서버용 비밀키 보호 방식으로 사용할 수 없습니다.
- 공공 메뉴 자료 버튼은 기존 시트를 엽니다. 원본 전체의 공유 대상을 임의로 넓히지 않았습니다.
- 알레르기 확인은 등록된 성분과 메뉴의 코드에 근거합니다. 정보가 없는 메뉴는 확인 불가로 안내하며, 대상자별 대체 식단을 확정·저장하는 별도 기능까지 구현한 것은 아닙니다.
